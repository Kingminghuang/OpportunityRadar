# 贴图正文写作（article-writer）

在 `topic-researcher` 之后运行：消费选题数据 `topic-brief.json`，写成一篇**中等长度、有来源、可直接作为贴图正文**的中文文章。文章先于贴图卡片存在——它是叙事的完整版本，`social-post-writer` 的卡片从这个叙事里提炼吸引点和推进节奏。

本写作技能 **不参与选题、不读取日报 JSON**。选题（选题标识、日报机会、GitHub 深度研究报告）由 `topic-researcher` 组装进 `topic-brief.json`，这里只负责把它变成文章。

不要直接调用微信 API；不要修改日报 JSON。

## 输入

- 读取 `topic-brief.json`（`topic-researcher` 产物，路径由调用方提供；默认在 `artifacts/topic-research/` 下按 `<date>--<slug>.json` 命名）。
- `topic-brief.json` 含三部分：
  - `source`：slug、报告日期/路径、`opportunityId`、issue 编号/URL；
  - `opportunity`：日报中该机会的完整对象（`opportunity`、`whyNow`、`evidence`、`verdict`、`score` 等）；
  - `research`：GitHub 深度研究报告 Markdown（含研究结论、用户与问题、证据、竞品与替代方案、市场与付费、最小可行版本、验证计划、风险与终止标准）。
- 用户没有提供 slug 却直接要求写文章时，先提醒运行 `topic-researcher` 选题，不要自行从日报挑机会。
- 读取 [`content-strategy.md`](../../../../skills/wechat-newspic-draft/references/content-strategy.md)，保持文章观点与贴图内容策略一致。
- 写作方法论参考传播型写作方法（Viral_Writer_Skill）的 11 个内容洞见维度（见下），但必须服从本文件的事实红线与字数约束。
- 去 AI 味参考 [`references/humanizer-zh.md`](references/humanizer-zh.md)（见“去 AI 味”一节）。

## 字数要求

- **正文 500–700 字**为宜；**最大不超过 1000 字**（`wordCount` 以中文字符计，不含标题与来源列表）。
- 标题 **20 字以内**（与贴图草稿标题上限一致），面向读者，不是日报标题也不是“机会雷达｜日期”。
- 段落短（每段 2–4 句），手机阅读友好；正文使用纯文本 + 空行分段，不插入 HTML、外部图片 URL 或 Base64。

## 贴图正文规范（借鉴小红书图文卡片）

微信公众号“贴图”按小红书图文卡片理解：用户先被封面停住，再用几张图快速得到一个观点或行动提示，不是读一篇长文。落实到正文：

- **开头直接上痛点/亮点**：前 3 句就让读者知道“这跟我有什么关系、为什么值得看”，不用“随着……的发展”这类铺陈开场。
- **中间干货密集**：把报告里的信号、证据压缩成可扫读的短句，一个段落只讲一个动作（理解矛盾 / 识别信号 / 评估机会 / 选择 MVP / 提出问题）。
- **结尾互动引导**：落到一个读者能回答的具体问题或验证指标，不用“欢迎关注、持续观察”。
- **口语化、亲近感**：像懂行的朋友在聊天，少术语、短句为主；不堆 emoji 当小标题（见“去 AI 味”）。
- **分点清晰但不成列表腔**：一句话能说清就不硬拆三点；确需罗列用自然短句，不做机械三段式。

## 写作方法（内部思考，不展示）

动笔前先走完传播型写作方法的 11 个维度构思，再按 OpportunityRadar 的事实红线改写：

1. **核心观点**：一句话能说清、读者会记住的立场；不是“今天有个机会”而是“X 正在悄悄变成 Y”。
2. **副观点**：2–3 个从不同角度支撑核心观点的层次（场景、证据、反面、延伸）。
3. **说服策略**：以数据驱动为主（日报有真实 Issue/证据），辅以类比隐喻或社会认同；故事段落只用作“假设场景”，必须标注是编辑场景而非报告事实。
4. **情绪触发点**：优先共鸣感（“这说的不就是我”）与紧迫感（“不验证就会出事”）；用报告里的真实故障制造张力。
5. **金句**：2–3 个可独立传播的句子，分布在开头、转折与结尾；从内容里自然长出来，不硬塞。
6. **情感曲线**：开头用反差/悬疑（成功提示 vs 实际故障），中段“紧张—释放”交替，结尾落到一个具体问题或验证指标。
7. **情感层次**：表层给信号与数据，中层给态度（“相信绿色提示是最贵的习惯”），深层让读者对号入座（“你维护的仓库有没有这种无人值守环节”）。
8. **论证多样性**：交替使用报告案例、数字、类比、反问、正反论证；避免通篇同一种说理。
9. **视角转化**：场景段落用第二人称带入，证据段落用第三人称陈述，建议段落用第一人称复数（“我们可以先……”）。
10. **语言风格**：短句、口语化、少术语；像懂行的人给朋友解释。禁止把 `opportunity`、`whyNow`、`verdict` 机械地改成三个小标题。
11. **互动引导**：结尾用开放式提问或“你会先把哪一步变成硬门槛”这类可回答的问题；不用“欢迎关注、持续观察”。

除上述维度外，正文**必须包含以下两个段落，不得跳过**（此前生成常遗漏，导致文章只有结论、没有来龙去脉）：

- **背景铺垫**：说明这个机会为什么现在出现——背后的技术、行业或用户行为变化是什么。例如“AI coding 从尝鲜变成主流，会话从临时聊天长成工作资产”。背景要能映射到 `research.markdown` 或 `opportunity.whyNow`，不能凭空铺陈时代背景。
- **价值论证**：论证这个机会为什么值得读者花时间——它解决什么真实痛点、谁在为此付出代价、不解决会怎样。价值要落在机制与成本上（丢数据、重搭上下文、多花时间、付费意愿），不是空喊“很重要”“值得关注”。

## 去 AI 味（口语化、去模板化）

参考 [`references/humanizer-zh.md`](references/humanizer-zh.md) 的规范，把正文改得像一个具体的人在说话，而不是模板生成：

- **删空话与套话**：删除“值得注意的是”“标志着重要转折”“赋能”“不断演变的格局”等不增加信息的句子。
- **拆公式结构**：不用“不仅……而且……”“不是……而是……”、机械三段式、每段同构；连续三句长度和结构相同时，拆掉或合并其中一句。
- **恢复自然节奏**：长短句交错，能用“是 / 有 / 可以”就不绕弯；允许关键词自然重复，不做同义词循环（“主人公 / 核心人物 / 核心角色”只留一个准确称谓）。
- **清理展示痕迹**：不堆 emoji、粗体、内联小标题；段落结尾不一味反问或甩金句，可用事实、代价或未决问题收束。
- **正确归因**：有来源就写来源；没有就删掉“专家认为”“多方指出”这类假权威，不虚构出处。
- **收尾不落套**：不用“未来可期”“令人期待”“迈出重要一步”这类万能积极结尾，改写成已确定的行动、未决问题，或直接收束。

## 事实边界（不可逾越）

- `topic-brief.json` 的 `opportunity`（日报字段）与 `research.markdown`（研究报告）是**事实来源**。凡事实句（谁、什么平台、什么故障、什么数字）必须能在 `sourceRefs` 中定位到 `opportunity.*` 字段或 `research.markdown:<章节>`。
- 研究报告（深度研究）通常比日报更新更完整：事实细节优先用研究报告，但不得偏离研究报告与日报的结论。两个来源说法冲突时以研究报告为准，并向用户说明差异。
- 允许的“扩展”只有四类，且要用语言标记：读者场景（“如果你在轮换数据库密钥……”）、因果解释（“可能意味着……”）、行动建议（“可以先做一个……”）、可证伪问题（“值得先验证是否……”）。
- **禁止**：编造市场规模、客户数量、收入、时间线、效果验证；把推测写成已发生的事实；引用研究报告和日报中都没有出现过的 Issue、公司或数据。
- 研究报告里的真实 Issue 链接与引用（如 Codex [#21803]）可以直接使用，但不要虚构不存在的链接或数字。

## 输出

写入 `article.json`（契约见 [`references/article-schema.md`](references/article-schema.md)）：

- `source`：从 `topic-brief.source` 继承——`slug`、`reportDate`、`reportPath`、`opportunityId`、`issue`；并保留 `opportunitySlugs: [slug]`（`create_draft.mjs` 依赖它校验与日报匹配）；
- `article.title`：**唯一主标题**，20 字以内、能吸引读者继续阅读，不输出备选标题；
- `article.body`：500–700 字正文（纯文本、空行分段），必须含“背景铺垫”与“价值论证”两段；
- `article.wordCount`：实际字数；
- `article.angle` / `audience` / `style`：供 `social-post-writer` 复用选题角度；
- `article.sourceRefs`：正文关键事实句的来源路径（`opportunity.*` 或 `research.markdown:<章节>`）。

可选同时输出 `article.md`（Markdown 排版版，仅供人工预览，不进入脚本链路）：**只输出一个主标题和正文，不再附“备选标题”章节**。

## 完稿检查（完成前逐项对照）

| 检查 | 合格标准 |
| --- | --- |
| 字数 | 500–700 字；任何情况下不超过 1000 字 |
| 标题 | 单一主标题，≤20 字、能吸引读者继续阅读、不是日报标题；无备选标题 |
| 背景铺垫 | 有一句/一段说明机会为何现在出现，能映射到 `research` 或 `whyNow` |
| 价值论证 | 有一句/一段说明机会的价值，落在机制/成本/真实痛点上，不是空喊“很重要” |
| 事实 | 每个事实句都能映射到 `sourceRefs` |
| 区分 | 事实 / 推论（可能、意味着）/ 建议（可以先）语言标记清晰 |
| 叙事 | 有读者场景或核心矛盾，不是字段复述 |
| 去 AI 味 | 无空话套话、无公式排比、无万能积极结尾、长短句自然 |
| 结尾 | 具体可回答的问题或验证指标 |
